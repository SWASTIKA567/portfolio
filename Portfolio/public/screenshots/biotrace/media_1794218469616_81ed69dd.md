## Project Overview

**BioTrace** is a cloud-based biodiversity intelligence platform designed to help researchers, environmental organizations, wildlife researchers, and government agencies analyze **environmental DNA (eDNA)** data and monitor biodiversity over time.

Environmental DNA is genetic material released by organisms into environments such as rivers, lakes, forests, and soil. Researchers can collect environmental samples and send them for DNA sequencing, producing datasets containing DNA sequences that can be analyzed to determine which organisms may be present in an ecosystem.

BioTrace provides a digital workflow that connects this scientific data with an accessible mobile and web interface. Researchers can create biodiversity monitoring projects, associate them with geographical locations, upload eDNA datasets, obtain taxonomic analysis, visualize biodiversity indicators, and compare results from different sampling periods.

The platform is designed not merely as a DNA-analysis tool, but as a **long-term biodiversity monitoring and collaboration system**.

---

## The Problem

Traditional biodiversity surveys can be time-consuming, expensive, and difficult to scale. Researchers may need to manually process sequencing data, maintain separate datasets, visualize results using different tools, and compare observations across different sampling periods.

There is also a collaboration problem: biodiversity studies conducted at the same geographical ecosystem may remain isolated across different researchers and organizations.

BioTrace addresses this by bringing the workflow into a single platform:

**Sample → Sequencing Data → Taxonomic Analysis → Biodiversity Insights → Historical Monitoring → Collaboration**

## How BioTrace Works

### 1. Create a Biodiversity Project

A researcher creates a project such as:

**"Yamuna River Biodiversity Monitoring"**

They can provide:

- Project name
- Sampling location
- GPS coordinates
- Ecosystem/environment type
- Sample type
- Sampling date
- Research description
- Project visibility and access permissions

### 2. Upload eDNA Data

After collecting an environmental sample and having it processed/sequenced in a laboratory, the researcher uploads the resulting dataset to BioTrace.

The platform can be designed to support processed datasets such as CSV/TSV files for the MVP, with FASTA/FASTQ-based sequencing workflows as an extended capability.

### 3. Bioinformatics Processing

The uploaded sequencing data is passed through a bioinformatics pipeline.

Depending on the dataset, the workflow can involve:

- Quality filtering
- Sequence preprocessing
- Denoising
- Sequence classification
- Reference database matching
- Taxonomic assignment

Tools such as **Kraken 2, QIIME 2, DADA2, or VSEARCH** can be integrated into the processing pipeline.

### 4. Taxonomic Identification

The resulting sequences can be classified against reference databases to determine their likely taxonomic identity.

Results can be presented hierarchically:

**Kingdom → Phylum → Class → Order → Family → Genus → Species**

For example:

> Animalia → Chordata → Actinopterygii → Cypriniformes → Cyprinidae → *Catla* → *Catla catla*

The platform also accounts for cases where the available sequence/reference information is insufficient for species-level identification.

### 5. Biodiversity Analysis

BioTrace converts taxonomic results into meaningful ecological information.

Researchers can view:

- Species detected
- Species richness
- Taxonomic distribution
- Biodiversity indices
- Species composition
- Potential invasive species
- Potential endangered/protected species
- Historical changes
- Sampling-location comparisons

### 6. Longitudinal Monitoring

Researchers can upload subsequent samples from the same or comparable location.

BioTrace stores historical analyses and enables comparison between sampling periods.

For example:

**January 2026 → July 2026 → January 2027**

The system can highlight:

- Newly detected species
- Species no longer detected
- Changes in species composition
- Changes in biodiversity indices
- Unusual ecological patterns
- Potential biodiversity risks

This turns individual eDNA analyses into a **long-term biodiversity monitoring system**.

## Mobile Application

The mobile application is designed around the researcher's workflow rather than simply presenting static information.

Key application areas include:

- User authentication
- Researcher profile
- Project dashboard
- Biodiversity project creation
- Sampling-location information
- Dataset upload
- Analysis status
- Taxonomic results
- Species information
- Biodiversity metrics
- Historical analysis
- Alerts and insights
- Project collaboration
- Responsive data visualization

### Dataset Upload Workflow

The mobile workflow allows researchers to:

1. Select a biodiversity project
2. Enter or select sampling information
3. Upload an eDNA dataset
4. Submit it for processing
5. Track analysis status
6. Access the resulting biodiversity report

The application therefore acts as the **researcher's primary interface with the computational bioinformatics pipeline**.

### API Integration

The mobile application communicates with the backend through APIs rather than performing computationally expensive bioinformatics operations directly on the device.

The architecture follows:

**Mobile App → Backend API → Bioinformatics/ML Pipeline → Database → Mobile App**

This separation allows heavy processing to occur on cloud/server infrastructure while keeping the mobile application lightweight and responsive.

### Results Visualization

Complex biological data needs to be presented in a way that researchers can understand quickly.

The mobile interface can surface:

- Species lists
- Taxonomic hierarchy
- Detection confidence
- Biodiversity scores
- Species trends
- Sampling history
- Location information
- Alerts
- Analysis summaries

This transforms raw computational output into an accessible research dashboard.

## Collaboration Model

BioTrace is designed around **research projects**, rather than treating an ecosystem as a single global project.

For example, multiple organizations may study the Yamuna River independently:

```text
Yamuna River
│
├── IIT Delhi Research Project
├── WWF Biodiversity Monitoring
├── Government Survey
└── Citizen Science Project
```

Researchers can discover public projects associated with a location, contribute where access is permitted, or create independent projects.

This provides a foundation for collaborative biodiversity research while preserving project-level privacy and permissions.

## AI/ML Component

The AI/ML layer is intended to complement established bioinformatics methods rather than replace scientifically validated taxonomic pipelines.

### Biodiversity Trend Analysis

Analyze historical observations to identify meaningful changes in species composition.

### Anomaly Detection

Identify unusual deviations from historical biodiversity patterns.

### Ecosystem Risk Assessment

Generate indicators based on biodiversity changes, invasive-species detections, species loss, and other available ecological signals.

### Automated Interpretation

Convert complex analysis results into concise researcher-friendly insights.

For example:

> "Species composition at this sampling location has changed significantly compared with the previous monitoring period, with two newly detected taxa and a decline in observed richness."

Such outputs should be treated as **decision-support insights**, not definitive ecological diagnoses.
